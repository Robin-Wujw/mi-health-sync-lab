# HealthKit 真机验收（T37）

当前状态：未执行。共享 Kotlin 策略测试不能替代 Xcode 构建或 HealthKit 真机回读。

在测试设备和专用授权账号上运行。只使用合成数据；保留包标识和签名团队，使用测试构建，不向个人健康数据库注入记录。不把原始健康值、路线、账号或设备标识写进验收报告。

1. **I01 运动提交**：测试主写入在提交前失败、提交结果未知，以及主记录已写入但可选详情失败。确认只在明确未提交时允许备用路径，提交结果未知时不再创建第二条运动，详情失败不能报全部成功。
2. **I02 高位旧版本**：先用同一 App 来源和稳定 ID 种入旧式元数据（仅同步 ID 和正整数版本），选一个大于 `2^53` 的旧版本。让新构建同步同 ID 的不同内容，且该内容旧式哈希低于已保存版本。回读确认仍只有一条、版本恰好加一、内容已更新。
3. **I02 重试与重装**：重复同步同内容，确认版本和记录数不变。保留 HealthKit 数据，卸载重装同 App 后再做一次相同内容和一次不同内容同步。分别验证不重复、能更新，且其他 App 写入的同名标识不受影响。再用一个从未出现的新 ID 验证版本从 1 开始。
4. **I02 多样本组合**：分别核对数量样本、睡眠分类、血压关联及其成员、运动及关联样本。回读比较出自本 App 的稳定 ID、版本、数量及关联关系；若关联丢失、读不到历史记录、历史高位版本被截断，或只见保存回调成功却未回读到新版本，判为失败。
5. **I03 温度**：只含皮温的输入不得生成体温；已确认的体温记录仍能写入。混合输入不得因为写入了体温就把未支持的皮温报为全部成功。

最少证据：提交 SHA、构建签名类型、iOS 版本、每条用例结果、读回的匿名版本/数量及是否仍具关联。完成同一提交的验收后才可设置现有的 `IOS_HEALTHKIT_VERIFIED_COMMIT` 门禁；失败或未测试时不附带 IPA。
