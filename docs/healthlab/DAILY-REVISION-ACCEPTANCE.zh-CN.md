# 自有日报迟到修订验收（D10 / T32）

状态：离线候选判定已实现；真实服务端未验收。正式版、预览版及后台任务均不得发送替换已有日报的写入。诊断中的 `gated_daily_revision_rows` 仅是候选计数，不能作为发布授权。

现有 instrumentation 的只读 `inspect` 路径可同时核对原始记录和完整来源日。`verified_daily_rows` 表示符合内容和唯一性检查的可见日报；`preserved_daily_rows` 表示看到了记录但不确认或改写；`gated_daily_revision_rows` 只统计原始数据已核验、明确返回了日报标签且归属指纹吻合的过期日报。完全相同的重复行也算多条，不能用作修订证据。此路径不提交数据、不预留写入、不更新归属账本。

新建日报时，客户端会在预留并发送前再查询一次。如这时发现同日报告、删除标记或待确认写入，放弃创建。复查不能替代服务端原子条件写入的证据：仍需在受控验证中确认真实并发行为。

## 受控验证

仅在另行批准的专用测试账号与目标地区执行。使用合成数据及隔离的完整来源日，不使用个人健康记录。先核对账号、地区、来源时区和测试目标；不能证明隔离则停止，不尝试回收或修改现有数据。

1. 在测试日创建一条本 App 日报，保留云端接受与随后完整回读的一致性证据。示例原始心率 60、80，对应均值 70。检查同日没有其他来源汇总，也没有待确认的写入。
2. 只追加和验证一条迟到的原始记录（示例 160）。先不要更新日报。分别读回原始记录、日报和官方显示，记录是否由服务端自动重算至 100，观察到的延迟，以及是否出现第二条日报。
3. 只有步骤 2 证实需要客户端修订，且明确批准一次写入时，才用隔离测试工具更新该专用日报。提交前再次比对原身份、确切归属指纹和来源日完整性。提交后分别回读目标与同日其他来源；确认服务端替换而非追加，且不会覆盖另一来源。若响应未知，不再提交，先回读核验。
4. 对照测试：外部或匿名来源、同日并存记录、删除标记、旧指纹变化、未读完整（含末页失败）、原始写入未知都不得改写。账号或地区变化后必须重做证据；未经验证的地区继续保留现有日报。

验收材料只保留构建 SHA、区域、用例、匿名状态和计数。不得保存账号、token、原始请求响应、源记录标识、原始健康值或可逆内容指纹。确认协议前不得移除门禁。
