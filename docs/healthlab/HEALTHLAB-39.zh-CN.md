# HealthLab .39：Zepp评分长时间同步与状态不收尾

日期：2026-11-13。版本1.0.6-healthlab.39（1000045）。用户反馈“Zepp评分→小米一直同步中，结束不了”。本轮未使用ADB，未读取手机当前卡住那一轮的日志；以下是代码确认的缺陷、针对性修复和本机验证，不能当成手机卡住根因的直接现场证明。

## 确认的代码缺口

1. MiZeppImportRunner对每条已匹配记录单独调用HealthImportLedger.markVerified，后者每次都是DataStore编辑事务。评分任务也包含密集压力点，数千个点会反复改写账本；即使内容已确认且没有变化，重复同步仍继续逐条写入。
2. 在逐点匹配、最终读前对照和查找缺失行时，对整段记录反复线性扫描，密集记录形成不必要的平方级开销。
3. Zepp阶段仅有单请求超时，没有整个阶段的时间预算；多页或多批请求可能累计很久。任务被取消时异常传播，但进行中的指标没有转为终态，UI可能继续显示“同步中”。

## 主流程修改

- 对首次读回已经匹配的记录，新增确认回执最多250条保存一次。已有相同持久指纹且没有pending的回执不再写盘。已有相同指纹但仍有匹配pending时，仍会核对预留并确认归属后清理pending，不能被快速路径跳过。
- 新上传仍保留每批最多50条、发送前持久预留、最后一次云读、发送后独立读回。读回成功的回执按该批统一保存；结果不明的记录继续pending。
- 云记录按时间建立索引，缺失判断使用时间集合；删除标记、同时间多来源和内容冲突仍全部保留在判断中。
- Zepp评分整个阶段设5分钟预算。自身预算到期转换成明确的未完成提示；父任务取消继续正常传播。超时不会清除发送预留，也不授权重新发送未知结果的请求。
- HealthRepository.syncAll结束或中断时，仅把仍在进行中的指标转为“同步已中断”。已经成功/无数据/失败的指标及数量、认证标记保持原样，结束后不再留下孤立转圈行。
- 没有新增按钮、修复入口或配置开关。
