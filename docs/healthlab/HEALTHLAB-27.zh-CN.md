# Health Lab 27：跑步心率、Zepp 分项与部分成功状态

版本 `1.0.6-healthlab.27` / `1000033`。沿用签名覆盖安装，保留小米与 Zepp 登录及同步设置，不需要 ADB 或再次电脑配对。

## 最新户外跑步心率

用户报告最新一场跑步完全看不到心率。电脑复用此前明确授权的短期小米会话检查：该记录的摘要是户外跑步，但 `proto_type=8`，关联通用训练文件；同时，原生跑步类型 1 的文件已经存在，包含完全相同的 54 个有效心率点。两份文件的观测值与时间戳相等。

本次只将这场已明确指认的运动摘要关联到原生跑步文件。运动身份、其他摘要字段均保留，没有新增运动，也没有重新上传文件体。独立读回通过，新进程重复修复为零文件上传、零摘要上传。

根因之一是文件格式依赖 Health Connect 是否返回首个路线点海拔：没有海拔时退回类型 8，海拔到达后改回跑步类型，后续读取又缺海拔时可能再次退回。新实现始终保留户外跑步/走路/徒步的原生协议类型，HR-only 文件的结构性海拔统一使用 IEEE NaN，海拔有效位不置位，不代表测量了 0 米。源海拔是否迟到不再改变心率文件内容或协议类型。受影响的户外文件使用有持久化预留的 timeline-v6 编码修订，其他运动维持原修订。

从对应小米 APK 转出的原始 Java 解析字节码在电脑执行：真实文件解析出 54 个有效点、2,347 个秒位置；所有有效值及时间戳的摘要与原文件一致。另以合成数据验证未知海拔结构不会吞掉心率。桌面验证仅替换日志和当前时区桥接工具，DEX 转换产物需 JVM `-noverify`；这不是手机页面实际显示验收，也不是完整 Android 渲染环境。

## 训练评分查询与真账号验证

真实 `get_sport_records_by_time` 接口排除等于 `start_time` 的运动。查询 `[运动开始, 运动结束)` 时原先返回 0 条，起点提前 1 秒后返回正确记录。读取器现请求提前 1 秒，再严格过滤为调用方的 `[from, until)`；分页游标和上限保持原契约。此前单次训练评分读取会因漏掉自己的目标而误报冲突，不能仅靠调整提示颜色处理。

对用户本次明确指认、且已成功修复文件关联的这场运动，使用生产 Zepp 来源与训练评分写入器补充了单次负荷、有氧效果、无氧效果，共 3 个字段。单场真实写入并独立读回成功；新进程复测核对 1 场、新写入 0、pending 0、conflicts 0，原摘要字段及文件引用保留。此次单场测试的归属依据是用户明确报告并授权修复该记录及本地修复预留，而非将任意云端手动来源当成已拥有。

未将此证据扩大为所有历史运动的训练评分写入成功。手机更新后仍根据自身已核对导入账本处理其他运动。没有目标导入记录的运动单独记作 skipped 并明确提示“请先同步这些运动”；同开始时刻多目标、结束时间矛盾、原有外部评分等真实冲突仍保留失败，不放宽覆盖规则。

## 截图中的状态

运动或 Zepp 评分已有已核对记录时，原界面仅在有 raw-import diagnostic 的情况下显示“部分已核对”。运动和 Zepp 分支通常只有 `verifiedCount`，因此被整个标成红色失败，运动分支甚至没有传递 verifiedCount。现在统一根据真实核对数量显示部分结果，并保留未确认数量。

Zepp 结果补充细分原因：原始 PAI/压力/周负荷待确认及冲突、单次训练评分待确认及冲突、未找到已核对导入运动、源数据不完整。未知写入继续保留 pending，不自动重传。截图中的 7 项尚未从更新后的手机报告逐项验收，不能宣称全部消失。

此外，FDS 部分不存在对象的地址响应会给出 URL 却没有 `obj_key`。新读取器只在实际 HTTPS 对象请求返回 HTTP 错误后保留该 HTTP 状态；可访问对象缺少解密字段仍属未知失败，不凭缺少字段推断对象不存在。真实旧通用训练 GPS 地址的独立 HTTP 控制读为 404。

## Zepp 连接和同步选项

同步页新增与设置页相同的 Zepp 连接入口。原来的云端总开关继续作为授权后的同步开关，下列选择独立保存：

- PAI（每日和近 7 天）
- 全天及手动压力
- 原生周训练负荷
- 单次训练负荷及训练效果

未选中的来源在正常同步中不请求也不写入。旧版本云端总开关的状态保持，旧用户首次分项默认与原先全部评分开启的行为一致；关闭全部分项会关闭云端总开关，重新勾选不会悄悄启用总开关。“读取源数据”是单独明确的查看动作，仍可预览全部来源。

Health Connect 的标准记录可以用于本机 Zepp 的运动、心率等；已安装 Zepp 不会自动授予本 App 其私有登录。PAI、周训练负荷、小米活力不是 Health Connect 的标准数据类型；活动强度/分钟不能冒充这些分数，见 [Android 官方数据类型表](https://developer.android.com/health-and-fitness/health-connect/data-types)。小米活力在界面显示为不可用项，并说明与 PAI 不同；恢复时间继续不推算。真实压力、PAI、原生周负荷沿用 .26 已验证的直接 Zepp 来源。
