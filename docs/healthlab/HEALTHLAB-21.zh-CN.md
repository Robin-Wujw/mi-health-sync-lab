# Healthlab 21：补齐续期凭据保存，默认开启体脂秤与 Zepp → 小米

版本：`1.0.6-healthlab.21 / 1000027`。沿用原包名与签名，直接覆盖安装。

## 本次退出能确定什么

用户在使用上次交付的最新版 .20 后，几天内再次遇到：

> Saved Mi session was rejected by Xiaomi (code 70016) — sign in again

这个提示来自保存的 passToken 续期接口被小米拒绝，不是普通网络错误被误当作未登录。截图没有续期前的请求日志，电脑目前也没有连接手机，所以无法确定这次凭据为什么被拒绝，更不能仅凭 70016 断定是小米主动踢号或某项风控。

检查 .20 后发现，上一版“立即保存新 token”的修复仍有两处遗漏：

1. 首次 serviceLogin 使用普通 `client.get()`，该调用会先缓存完整响应正文；解析完 JSON 后才保存响应头中的新 token。小米已在响应头发出新 token 时，如果正文传输中断或者无法解析，新 token 仍会丢失。
2. 首次结果缺少 ssecurity 时，还会额外请求一次 serviceLogin。这个请求可能再次轮换 token，但只有整个补取过程返回后才通知持久化；读取正文失败时，会留下第一次轮换后的旧 token。

上述缺陷在 .20 源码上通过模拟服务器复现，新增 3 项测试全部失败，原有 8 项通过。它们证明了代码中的丢失路径，**不证明用户这次恰好走了其中一条路径**。

## .21 的修复

两处 serviceLogin 都改为流式接收，在读取或解析正文之前，先将响应头 / Set-Cookie 中的新 passToken 保存到 DataStore。保存步骤不被协程取消打断；后续正文、补取或 STS 失败仍按可重试失败处理。下一次使用已经保存的新 token 续期。

JSON 中的 token 兼容逻辑与真实 70016 / 安全验证的处理保留。已经被小米作废的凭据不能靠升级恢复；用户已经重新登录的会话会继续使用。

Ktor 接口依据：[HttpStatement.execute](https://api.ktor.io/ktor-client-core/io.ktor.client.statement/-http-statement/execute.html)。只在 execute 作用域内读取响应，向外传递响应头和已读取的文本。

## 默认设置和重新登录

按用户要求，首次启动 .21（包括覆盖升级）时应用一次默认配置：

- 开启“体重与体成分”和“传回体重时附带体成分”。
- 开启全部 5 项 Zepp → 小米项目：心率、静息心率、睡眠、HRV、血氧。
- 保留其他已选项目、同步天数和自动同步开关。

默认配置只应用一次；之后用户关闭某项，重启或重新登录不会再替用户打开。

退出登录原来会清除整份设置文件中的同步选项，导致重新登录后要重新点选。现在只清除账号凭据、账号地区及上一次会话的同步状态；同步开关、天数、自动同步和上传核对账本保留。Health Connect 的系统授权仍由系统控制，首次缺少读取权限时按正常流程请求。

## 验证范围

新增回归覆盖：首次正文损坏、首次正文中断、二次补取正文中断，以及默认配置、旧设置升级只执行一次、重新登录保留配置和清除旧错误状态。

完整测试数量、APK 校验结果和构建记录见同目录交付的 `validation.json`、`build-healthlab21.log`。本版没有真机安装或真实云端写入，尚未验证用户设备连续多天的登录保持情况；不能承诺永不需要重新验证。

## 安装

直接覆盖安装 `.21.apk`，不要卸载旧版。打开应用后体脂秤和 Zepp → 小米默认已开启；若已经重新登录，无需再次退出。后续登录会保留自己的选项。
