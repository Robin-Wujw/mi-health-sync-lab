# Health Lab 23：Zepp 云端评分接入

版本：`1.0.6-healthlab.23` / `1000029`，包名沿用 `com.bettermifitness.sync.healthlab`。

本版参考用户指定的 `D:\MyCodes\Vitalis`，独立实现 Zepp 云端登录、事件读取和评分转换。Vitalis 仅作源码参考，未读取其运行目录中的凭据、数据库或个人健康记录，未改动 Vitalis。既有 .22 交付及真机验收保留。

**当前验收状态：本地实现与合成测试；新增评分未完成实际账号云端写入或手机页面验收。** 无 ADB 操作，未向手机安装本版。后续需要在新版设置中连接用户的 Zepp 账号；不需要 ADB，也不要在聊天中提供密码。

## 使用

1. 覆盖安装本版 APK，保留原有小米登录、同步设置和防重复账本。
2. 设置 →「Zepp 云端评分」→「连接 Zepp」，输入 Zepp 邮箱或手机号、密码及两位国家代码，例如 CN。
3. 点「读取源数据」先检查账号实际提供的评分。此操作只读 Zepp，不写小米。缺少某项数据不意味着零分。
4. 开启「将可映射的评分同步到小米」，再执行原有「立即同步」。开启自动同步后，同一路径由后台任务调用。新开关默认关闭，既有 Health Connect 同步保持原设置。
5. 根据同步页的已核对、待处理数量判断结果。网络请求成功不等于导入成功，上传后还要独立读回。源扫描最多最近 31 天，长时间范围不会静默扩大为全历史。

Zepp 密码仅驻留本次登录过程，不保存。会话令牌随应用私有偏好保存，Android 系统云备份和设备迁移排除此偏好文件；断开 Zepp 会清理会话并关闭新开关，保留已上传数据及防重复账本。会话失效后最多尝试一次登录令牌续期，续期协议仅合成测试通过，未据此宣称实际账号长期稳定。

## 各项数据的准确范围

| 数据 | 本版实现 | 验证边界 |
| --- | --- | --- |
| PAI | 读取 `PaiHealthInfo`；保留当日、累计及低/中/高强度分数；五项齐全并有源时区时映射到小米 `pai` | 小米 3.59.2 的原生华米转换器和 JSON 项模型已核对；实际账号读回、卡片显示待验收 |
| 全天压力 | 读取 `all_day_stress.data`；按原时间写 `stress` | 只接受整数 1–100；0、255、布尔值、非有限数及无源时区的点不写；不冒认融合样本的设备归属 |
| 手动压力 | 读取 `single_stress`，独立写 `single_stress` | 与全天压力分开，不将平均值展开成采样点 |
| 原生周训练负荷 | 读取 `WatchSportStatistics/SPORT_LOAD`；只接受 `dayId`、`weeklyTLSum` 这一明确契约 | `currentDayTL` 和三个阈值按存在情况保留；缺失不补零，不用 ATL 替代 |
| 单次训练负荷、训练效果 | 读取账户级 `run/history.json`，负荷保留原值，`te`/`anaerobic_te` 从十分位转换到 0–5 | 只为本应用已拥有、能唯一匹配起点及已知终点的运动补字段，不新建第二份摘要；保留原轨迹、心率和原生附加字段 |
| ATL / CTL / TSB | 读取 `exertion/algo_result`，在设置中按 Zepp 原名显示，包括 Total 系列和合法负值 TSB | 厂商估计，公式及 Total 语义未充分验证；不冒充小米周负荷或活力 |
| 小米活力 | 已查明独立 `VitalityItem`，字段与 PAI 不同 | **尚未完成来源、算法和目标写入验证，本版没有活力转换** |
| 恢复时间等其他训练评分 | 保留明确待办 | **没有可靠源单位和时间契约，不推算恢复时间；不能宣称训练评分已全覆盖** |

## 协议依据

Zepp 端参考 Vitalis 的 `adapters/zepp/client.py`、`login.py`、`streams.py`、`parser.py`、`parsers/supplemental.py`。这些文件提供接口与单位线索，不构成本应用实际账号验证。未复制 Vitalis 的服务、数据或测试样本。

小米端直接核对本地公开 APK 中的 `HmPaiDataParse`、`HmAllDayStressParse`、`HmTrainingLoadParse`、`FitnessDataRecorderImpl`、`OneDayPaiReport`、`StressItem`、`TrainingLoadItem`、`VitalityItem` 以及 `SportBasicReport`。这是 Mi Fitness 3.59.2 的静态协议证据，不替代云端接收和客户端显示验收。摘要文件及源文件 SHA256 见交付的 `protocol-evidence.json`。

## 一致性和失败处理

同一来源事件选择完整的新修订，不从旧修订补缺失字段；冲突设备或同目标不同值不擅自择一。不同 Zepp 和小米账户的账本隔离。未知时区不借用手机时区。

评分上传沿用「预读 → 最后一次预读 → 持久化预留 → 单次上传 → 独立读回」。超时、进程中断或丢失回执后，待核对的目标不会自动重传；只有相同来源、内容和时区的读回能够核销预留。外部修改过的内容以及没有本地所有权的冲突记录不覆盖。部分评分成功、部分待处理时，同步总结果保留已核对数量。

运动补充分数以已验收运动为前提。其他源运动只读取并保留源信息，不用时间相近或按天汇总来猜测归属。恢复时间、活力、负荷等级和训练感受均不编造。
