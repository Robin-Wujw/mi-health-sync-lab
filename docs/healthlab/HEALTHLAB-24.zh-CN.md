# Health Lab 24：Zepp 云端评分与电脑本地验证配对

版本 `1.0.6-healthlab.24` / `1000030`，包名 `com.bettermifitness.sync.healthlab`，沿用既有安装签名，可覆盖 .22，无需卸载或 ADB。

## 已完成的实现与检查

Zepp 独立云端来源已接入设置、普通同步和后台同步，默认关闭新开关。实现 PAI、全天/手动压力、原生周负荷，以及为已拥有的唯一运动补充单次负荷和有氧/无氧训练效果；ATL/CTL/TSB 保留 Zepp 含义供查看。没有把 PAI 改名为活力，没有推算恢复时间。

在用户明确授权复用账号后，从 Vitalis 运行库以只读方式取得其已授权 Zepp 会话，仅在内存解密用于读取；没有修改 Vitalis 运行库。生产 Kotlin 客户端真实读取最近七天，返回 7 天 PAI、约 1,600 个压力点、9 场运动和 8 份负荷日报。滑动窗口会使压力点数变化；以每次报告的数量为准。未将原始健康值、轨迹、账号或令牌写入交付报告。

真实接口验证修正了两处静态证据无法确认的差异：

- `SPORT_LOAD` 区域云使用 ISO `dayId`、`wtlSum`、`currnetDayTrainLoad` 和 `wtlSumOptimal*`，与旧设备转换器的 `weeklyTLSum` 命名不同；两种已知契约分别识别，不猜测未知键。
- 全天压力事件没有源时区。绝对时间和值保持原样，目标显示时区采用手机当前系统 IANA 时区对各观测时刻求偏移；这是传输显示元数据，不记作原始源时区，也不据此补写日报。设置页明确说明这一策略。未提供目标显示时区的纯映射调用仍拒绝未知时区。

本版 958 项测试通过，包含 TLS 实际握手/传输、错误证书不发送任何负载、过期链接不发送、账号与修订隔离、满页不宣称完整和不确定上传不重传。Lint 0 错误、24 个既有警告，Detekt、两个 APK 构建、签名与 16KB 对齐通过。iOS 不在本次真机/平台验收范围。

## 为什么增加本地配对

网页登录、STS 页面显示成功，以及健康接口可用不是同一件事。经过用户授权连接 Chrome 后，浏览器会话可以读取，但所取得的网页 `psecurity` 不能冒充健康接口的 `ssecurity`；健康只读请求在各分区返回 HTTP 401。该尝试没有产生评分写入，不能报告成真实云端导入成功。

电脑验证改为复用同步 App 已有的健康短期会话，避免再次登录、反复输入验证码，或让电脑持有并轮换手机的长期 `passToken`。配对流程：

1. 手机与电脑在同一局域网，打开电脑提供的配对页，下载并覆盖安装 .24。
2. 回到配对页点击「连接验证电脑」。
3. App 显示接收方局域网地址和证书 SHA256 前 12 位。确认与电脑页面一致后，点击「加密发送短期会话」。
4. 电脑收到会话后先独立读云端；只有该检查通过才开始少量评分上传、读回和重复执行。

App 的导出入口只接受有期限的私有 IPv4 接收方与固定证书指纹；不接受公网、DNS 名称、回环/元数据地址、重复或额外参数。TLS 握手校验二维码绑定的证书，禁止重定向，负载和响应有大小限制。只有在手机明确确认接收方后才读取凭据和发送；界面禁止截图，不记录凭据。发送内容不含密码、长期 `passToken` 或健康样本。

电脑配对码 15 分钟有效且只能使用一次；收到会话加密保存到本地私有验证目录，不进入仓库或交付。App 没有新增远程后台命令、自动静默导出或长期控制入口。账号测试结束后应关闭临时配对服务和相关浏览器连接。

## 验收状态

本地实现、合成回归和 Zepp 实际只读来源验证已完成。小米短期会话配对及后续真实评分写入以交付 `validation.json` 和新增本地云端报告为准；**手机发送了会话，也不自动等于健康接口验收或页面显示验收**。

PAI 和压力分数的原生页面显示、活力的真实来源与等价计算、恢复时间及其他训练评分，均不能用本地测试数量代替验收。用户明确延期的旧运动客户端缓存问题不在本版重新处理。
