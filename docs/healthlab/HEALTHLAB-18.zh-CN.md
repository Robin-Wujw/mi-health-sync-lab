# Healthlab 18：静息心率自动修订与安静的正常状态

版本：1.0.6-healthlab.18 / 1000024；沿用原包名和签名，已覆盖安装到连接的手机。

## 静息心率

用户日志中的两条来源记录映射为同一个日期的静息心率最小值，云端已有日值与新值不同，.17 报 `CONFLICT / bpm`。现场确认该目标仍有本应用上传归属，云端底稿未变，但云端省略了 `zone_offset=0`。原修订策略既未接入静息心率，也要求云端必须显式返回时区，因而无法自动处理。

.18 将静息心率接入正常同步的修订流程：仅处理本应用上传、完整云端底稿仍匹配、来源有效且日期编码明确的目标。`date_time` 必须等于原目标的 UTC 编码日期，目标必须对齐日边界；省略零时区只在这种日期语义下允许。普通心率的瞬时时区仍严格检查。提交前重新核对云端底稿、归属和 pending，提交后读回验证；云端扩展字段保留。

同时补齐所选来源日期在滚动窗口之前的静息心率测量，按同一源日的有效实际测量取最小值，防止 1 天窗口截掉较早的低值后把日值抬高。补读结果只用于已经选中的来源日期；缺少源时区、日期不同、同刻矛盾等继续拒绝，不猜测日期。

## 界面

- 心率冲突秒、HRV 无明确睡眠归属等正常过滤，使用普通完成状态。首页、设置、同步页不再写“含跳过”、跳过数量或普通提醒。
- 完成行保留核对数量，详细的正常警告和正常诊断按钮不再默认展示。显式单条诊断模式仍可查看报告。
- 没有源数据使用中性状态，不再显示警告横幅或长篇原因推测。真正的上传失败、未读回、云端冲突或源数据错误仍显示未完成/错误，并保留诊断入口。
- .17 已保存的 `completed_with_skips` 也直接按普通成功显示，旧消息中的跳过数量不再进入首页，无须清数据。

这些改变调整正常状态的呈现；诊断报告仍保留内部计数，不会把真实未完成记录算成成功。
