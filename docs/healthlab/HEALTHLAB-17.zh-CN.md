# Healthlab 17：自动处理未完成导入、HRV 与 1 天范围

版本：1.0.6-healthlab.17 / 1000023。沿用原包名、签名，可覆盖安装。

## 本次实际解决的问题

心率的 `HEART_RATE_SOURCE_POINT_EXCLUDED` 是同一源秒内数值矛盾，仍按规则跳过。`precheck_mismatch_field.bpm` 则表示源计划与云端已有心率不同，两者不能混为一谈。

- 正常同步会自动修订本应用此前上传、且云端完整底稿仍未变化的心率点。必须保留同一目标、可靠时区、当前无歧义源值；提交前重新核对云端底稿、上传归属和 pending 状态，提交后逐条核对。其他来源、删除标记、归属不明或已变化的云端内容仍保留。
- HRV 先读取所选范围内的完整睡眠，再补齐覆盖这些睡眠的 HRV 样本。切换 1/7/30 天不会仅因截取半段睡眠而产生不同摘要。完全相同但 ID 不同的睡眠视为同一等价分组；相邻睡眠边界采用半开区间，真实重叠的归属不明样本跳过并计数。
- HRV 的已有摘要也可自动修订，但仅限本应用上传归属明确、云端底稿未变、睡眠时间线与所有原有睡眠字段均匹配的目标。只更新三个 RMSSD 摘要字段，保留云端扩展，不修改睡眠内容。原始算法仍是实验性的睡眠区间 RMSSD 样本摘要，不宣称转换成小米原生 HRV 算法或恢复 HRV 曲线。
- 正常同步会先核对旧 pending；心率、血氧中符合完整预检的旧 pending 自动使用持久化的一次恢复额度。每次最多 300 个，单个既有值冲突不阻止独立可恢复目标；提交后未核对、网络失败、已消耗的恢复额度仍会停止继续尝试。本次刚产生的不确定上传不会在同一轮立即重发。
- 已移除同步页单独的“处理未完成数据”按钮。所有已启用指标都走正常同步；无须再通过额外按钮触发以上处理。仅支持读取核对的其他指标，不会被扩展成无条件重传或覆盖。
- 正常跳过显示“已完成，含跳过”，数量与真实上传、核对数量分开。HRV 跳过归属不明、清醒或无匹配睡眠的样本，不再单独导致整次任务显示“部分”。真正未解决的云端差异仍报告未完成。
