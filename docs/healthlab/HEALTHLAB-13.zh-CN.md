# Mi Health Sync Lab 1.0.6-healthlab.13

版本 `1.0.6-healthlab.13 / 1000019`，同签名覆盖安装，保留登录、权限与导入账本。

## 这次解决什么

.12 一天实机检查确认：有效心率 1327 点全部云端匹配、待确认为 0，仍有一个源记录在完全相同的毫秒时刻提供不同心率值。进一步检查时窗口移动为 1325 个有效目标，仍全部匹配，冲突点没有云端候选。它不是秒数取整导致的误判。

.13 将此类点从“阻断整个心率导入的源错误”改为**明确跳过的异常时间点**：

- 仅针对同一个最新源记录内部、相同毫秒时间、多个不同且范围有效的心率值。整个目标秒排除，不选第一个/最后一个、不取均值、不移动时间，也不从同秒其他记录借值。
- 其他有效心率照常导入和核对。重复执行不会为排除点创建待上传锁，不会重传它，也不会删除或修改 Health Connect 原记录。
- 该日期仍不能声称生成了完整日报，其他满足条件的日期不受影响。未知日期影响仍保守处理。
- UI 显示“已核对，含跳过”，诊断显示 `excluded_source_points` 和 `COMPLETE_WITH_EXCLUSIONS`。跳过点不计入已核对数，整个同步仍保留部分完成提示，不显示全部成功。
- 不同源记录之间的冲突、同秒不同毫秒的精度碰撞、云端冲突、来源修订冲突和旧 pending 均保持原保护规则。此版本不处理此前 300 条旧待确认的真实补传。
- 以后 Zepp 提供一致的新修订，重新映射会自动纳入该点；没有永久黑名单，不阻止修正后的真实数据。

## 验证

675 项自动化测试通过（composeApp 615、miclient 60），新增 7 项。覆盖单记录自相矛盾、相邻正常样本保留、日报日期隔离、多点统计、重复相同值不误排除、新修订恢复、独立云端冲突继续阻挡、跳过点不虚增成功数及全局部分完成状态。

Android 主包和同签名测试 APK 已构建；签名、版本、16 KB 对齐、完整性和累计补丁还原见 `validation-healthlab13.json`、`patch-validation.json`。iOS 未构建。

准备覆盖安装时 ADB 未检测到授权手机，因此新包尚未在手机执行。已请求用户重新连接；最终连接状态以交付消息为准。本轮没有真实健康上传，也没有用未经验证的值去填补冲突点。

## 安装与检查

直接覆盖安装主 APK，不卸载、不清除数据。选择一天范围重新同步，目标是“有效点已核对，异常点已跳过”，而不是宣称所有源数据都已修正。真实新增有效数据仍按照正常同步流程提交。

连接电脑时可用独立测试 APK 的 `verify-existing-heart` 对一天范围执行正常 RAW 预检，新的写前预留和 POST 都被禁用；遇到尚未上传的新点会在预留前阻止并报告。工具沿用 1～27 天只读检查范围，主应用 30 天权限流程保持 .12 行为。
