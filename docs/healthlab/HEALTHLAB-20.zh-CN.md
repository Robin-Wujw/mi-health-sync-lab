# Healthlab 20：以 Zepp 为准，减少登录“突然过期”

版本：1.0.6-healthlab.20 / 1000026；沿用原包名和签名，可覆盖安装。

## 以 Zepp 为准

用户的数据都从 Zepp 同步，并明确要求以 Zepp 为准（2026-11-06）。

.19 及之前，云端记录和 Zepp 不一致时，只有账本能证明这条是本 App 写的，并且上传后没变过，才会更新；睡眠还要打开一个默认关闭的开关，已有 HRV 摘要的睡眠打开开关也不更新。所以 Zepp 事后修订某一晚，或者账本因退出登录丢失后，这一晚的睡眠和 HRV 就会一直报冲突。

.20 的规则：

| 云端情况 | 处理 |
|---|---|
| 没有这条记录 | 上传 |
| 内容相同 | 不写 |
| 内容不同，是一条明确的 `default` 记录（不管谁写的） | 按 Zepp 更新，然后读回核对 |
| 上次上传结果未确认（pending） | 不动，继续报告 |
| 同一位置有已删除的记录 | 不动，继续报告 |
| 同一位置有其他来源的记录 | 不动，继续报告 |
| 同一位置有多条内容不同的记录 | 不动，继续报告 |
| 时区和 Zepp 不同 | 不动，继续报告 |
| 云端字段不完整或无法解析 | 不动，继续报告 |
| 写入前的最后一次读取发现记录变了 | 本次不写，下次同步再处理 |

范围是睡眠、HRV、心率和静息心率。更新只替换本 App 映射的字段，云端自带的其他字段保留。

同步时先跑睡眠，再跑 HRV。睡眠更新时旧的 HRV 摘要先留着，HRV 紧接着按 Zepp 的样本重新计算。没有开启 HRV 导入时，旧摘要会留在更新后的睡眠上。

已经报冲突的那一晚，装上 .20 后再同步一次就会被更新。

血氧和小米日汇总没有改：血氧日志里没有这类冲突，而且有分钟对齐的特殊规则；日汇总可能由小米自己生成，继续保留。

## 登录“突然过期”

查到两个问题，都已修复：

- **新 token 会丢。** 小米每次刷新都会换新 passToken，并很快废掉旧的。原来要等整个刷新成功才保存新 token，后面的 STS 步骤一旦断网或被系统中断，新 token 就丢了。下次刷新带的是已废弃的旧 token，小米返回 70016，只能重新登录。现在拿到新 token 立刻保存。
- **误报未登录。** 一次全部失败的同步里，只要出现过认证错误，就可能提示“未登录，请重新登录”，哪怕只是刷新时网络失败，或者刷新刚成功。现在只有小米明确拒绝刷新（70016 或要求重新验证）才要求重新登录，其他情况显示为可重试的失败。

修复之后仍可能需要重新登录，比如小米要求安全验证、修改了账号密码，或者 App 很长时间没有运行。用户上次过期的真实原因无法从现有信息确定。

## 设置和诊断的变化

- 移除“允许更新本应用已上传的睡眠”和“允许为旧版已核对的睡眠补齐 HRV”两个开关，它们已经没有作用。
- 诊断格式升到 v3：`attempted_owned_revision_rows` 等改名为 `attempted_revision_rows`、`verified_revision_rows`、`eligible_revision_rows`，并去掉 `unowned_conflict_rows` 和 `changed_owned_baseline_rows`。`sleep_conflict.ownership.*` 保留，只用来说明记录来历，不再决定能否更新。
- PC 测试脚本的 `repair-one-owned` 改名为 `repair-one`，并支持睡眠。

## 验证

- 792 项本地测试通过（composeApp 732、miclient 60），比 .19 多 22 项。旧测试里断言“不能覆盖”的部分已按新规则改写；待确认、已删除、其他来源、时区变化等仍然阻止更新的情况都有测试。
- 变异测试：逐项撤掉本版的修复或保护条件，共 30 项，每一项都有测试失败。
- 修复前，登录相关的测试复现了失败：STS 步骤失败后，下次刷新带的是旧 token，小米返回 70016。
- 主 APK、测试 APK、Android release lint 构建通过，Detekt 0 项。签名、版本、16 KB 对齐和累计补丁恢复结果见交付目录的 `validation.json`、`patch-validation.json`。

## 尚未验证

- **没有真机运行。** 本版没有安装到手机，也没有写入真实健康数据。
- **替换整条睡眠没有在真实云端跑过。** .17 在真机上验证过按同一身份更新 HRV 摘要，但没有验证过改写入睡时间和阶段。如果云端没有按预期替换，读回会发现不一致，这一晚会变成“待确认”并继续报告，不会自动重试，也不会被当成成功。
- 登录修复基于模拟的账号服务器，没有在真实小米服务器上触发过。
- iOS 未构建（Windows 主机）。

## 手机上怎么确认

覆盖安装后，选择包含那一晚的范围同步一次，复制睡眠和 HRV 的诊断：

- 睡眠：`outcome=COMPLETE`，`sleep_conflict.verified_revision_rows=1`。
- HRV：`verified_revision_rows=1`。
- 再同步一次，两者的 `attempted_raw_rows` 都应该是 0。

如果是从 .18 直接升级，第一次同步还会把小米 → Health Connect 的记录重写一遍，之后只写变化的记录，确认方法见 [Healthlab 19](HEALTHLAB-19.zh-CN.md)。

## 已知限制

- Zepp 如果改了某晚的**起床时间**，会被当成新记录上传，旧记录仍留在云端。本 App 没有删除云端记录的能力。
- 小米 App 页面可能仍显示旧的日汇总，因为日汇总没有改。
- 本应用不覆盖其他设备来源的记录。如果同一时间有手表直接写入小米的数据，这条仍会报告。
